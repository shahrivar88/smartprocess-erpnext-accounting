# استاندارد تأثیرات بین‌ماژولی SmartProcess

این سند قرارداد توسعه برای تمام اپ‌های اختصاصی SmartProcess است. اپ حسابداری آن را در تب «تأثیرات بر سایر ماژول‌ها» پیاده کرده است. اپ‌های بعدی باید همین الگو را رعایت کنند.

## اصل

هر قابلیت اختصاصی که رفتار استاندارد ERPNext یا ماژول دیگری را تغییر می‌دهد باید در تنظیمات همان اپ مالک، با زبان فارسی، قابل مشاهده باشد. کاربر باید بداند چه چیزی عوض شده، کجا اثر می‌گذارد، و چگونه به رفتار استاندارد برگردد.

## اطلاعات الزامی برای هر قابلیت

| ستون | محتوا |
|---|---|
| نام قابلیت | عنوان فارسی همان تنظیم یا محافظ |
| ماژول مالک | اپی که کد را نگه می‌دارد |
| DocTypeهای تحت تأثیر | فهرست دقیق اسناد یا ماژول‌ها |
| توضیح اثر | جمله فارسی روشن؛ بدون اصطلاح مبهم |
| وضعیت | فعال / غیرفعال، یا «فعال (محافظ الزامی)» |
| روش بازگشت | مسیر خاموش‌کردن یا توضیح اینکه خاموش‌کردن از تنظیمات مجاز نیست |

## دو طبقه قابلیت

1. **اختیاری.** کلید کنترل مستقل در تنظیمات داشته باشد. خاموش‌کردن باید رفتار استاندارد ERPNext را برای همان سند برگرداند. مقدار ذخیره‌شده و قاعده سرور نباید عوض شود مگر اینکه قابلیت خودش یک قاعده تجاری صریح باشد و برچسب آن این را بگوید.
2. **محافظ الزامی مالی یا امنیتی.** فقط توضیح شفاف. کلید خاموش‌کردن ناامن ایجاد نشود. بازگشت فقط با مجوز جداگانه و تغییر کنترل‌شده در اپ مالک.

## محدودیت اجرا

- Core ERPNext یا Frappe ویرایش نشود.
- Hook مشترک فقط وقتی عوض شود که اثر آن روی همه سایت‌های همان bench بررسی شده باشد.
- Restart، Migration یا Recreate زیرساخت مشترک بدون بررسی اثر روی CRM و بدون مجوز انجام نشود.
- قابلیت آزمایشگاهی روی سایت زنده بدون تأیید جداگانه فعال نشود.

## محل نمایش

در تنظیمات همان اپ، یک تب یا بخش با عنوان «تأثیرات بر سایر ماژول‌ها» اضافه شود. فهرست باید از همان منبعی ساخته شود که boot یا فرم تنظیمات می‌خواند تا وضعیت با کلیدهای واقعی یکی بماند.
