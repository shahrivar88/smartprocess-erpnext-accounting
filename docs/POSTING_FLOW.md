# جریان ثبت تبدیل

## پیش‌نویس

ذخیرهٔ Draft هیچ `GL Entry` یا `Payment Ledger Entry` نمی‌سازد.

## Submit

1. سرور همهٔ مبلغ‌ها، نرخ‌ها، جهت‌ها و ارزها را دوباره محاسبه می‌کند.
2. اگر دو ارز خارجی متفاوت باشد، ثبت متوقف می‌شود.
3. اگر بدهکار و بستانکار پایه برابر نباشد، ثبت متوقف می‌شود.
4. اگر حساب دریافتنی/پرداختنی باشد و طرف حساب خالی باشد، ثبت متوقف می‌شود.
5. `build_gl_map` دو ردیف GL می‌سازد.
6. `get_gl_dict` فیلدهای مشترک از جمله `voucher_type` و `voucher_no` را روی خود سند تبدیل می‌گذارد.
7. `make_gl_entries` ردیف‌های بومی را ثبت می‌کند.

## Cancel

1. سند به حالت لغوشده می‌رود.
2. `make_gl_entries(cancel=1)` مسیر معکوس native را صدا می‌زند.
3. ردیف تاریخی GL حذف نمی‌شود.
4. اگر تخصیص فاکتور در نسخه‌های بعدی اضافه شود، باید از همین مسیر native برگردد.

## تخصیص فاکتور

در این نسخه `against_voucher` به فاکتور فروش/خرید ست نمی‌شود.
